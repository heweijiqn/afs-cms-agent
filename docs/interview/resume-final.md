### 项目经历

#### 广告投放管理平台与多智能体优化系统 ｜ 独立开发 ｜ 【2025.01 – 2026.11】

`Java 17` `Spring Boot 2.7` `MyBatis` `LangGraph4j 1.5.14` `LangChain4j 1.0.1` `H2 / MySQL` `React 18`

- 独立交付 **245** 个主源码文件、**52** 个 Controller、**42** 个 MyBatis Mapper 的投放中台，
  覆盖活动管理、渠道报表、内容素材、规则引擎、审批流与开放 API；**194 MB** 单体 JAR 内嵌前端产物，
  一条命令冷启动 **8.5 秒**，零外部凭据可完整演示。
- 基于 LangGraph4j 编译态 StateGraph 编排 **8 节点**优化闭环
  （上下文摄入 → 策略规划 ⇄ 工具执行 → 护栏评审 ⇄ 自我反思 → 方案定稿），
  用条件边实现 STANDARD / DEEP / RULES_ONLY 三种模式；无模型配置时自动降级为确定性规则分支，
  保证功能可用性不依赖外部 LLM。
- 设计 **8 个只读 Function Calling 工具**（逐日趋势、国家拆分、创意上下文、规则上限、同业基准、
  历史审批、场景目录、预算试算），并统一做输出截断（6500 字符）与异常降级
  （`{"available":false}` 而非抛栈），把模型约束在「只能基于真实数据推理」。
- 用「护栏即节点」解决 LLM 不可信：`guardrail_critic` 对结构化输出做**枚举/幅度/符号/结构**四类硬校验，
  违规写入反思反馈触发重规划（上限 1 次），越界建议无法进入审批队列；
  三条上限（用户请求 / 规则上限 / 安全策略）取最小，默认最保守。
- 实现四级安全治理：SHADOW / COPILOT / AUTONOMOUS 三级模式、全局 Kill Switch、
  单次调幅上限 ±20%、日累计预算变动上限 500，均按 `optimization_ledger` 已提交台账实时校验，
  从「按建议算」改为「按落库算」，防超发。
- 实现 LangGraph4j JDBC 检查点（`BaseCheckpointSaver`）：`agent_checkpoint` 按 threadId 隔离、
  `MERGE` 保证幂等、序列化失败逐字段降级，支持重启续跑与审批过程追溯。
- 用 SSE 构建节点级可观测性：`agent_execution_trace` 落库 + 迟到订阅回放 + 断连自动剔除；
  本地工作区已真实跑过 **78 次优化运行 / 461 次节点执行 / 395 次工具调用 / 127 万 token**，
  token 与耗时分布可在控制台复查。
- 实现开放 API 签名鉴权（排序取头 + body MD5 + **12 分钟**时间窗 + nonce 一次性）与
  operator / reviewer **双人审批**（BCrypt、路径级 RBAC、STATELESS），渠道凭据 AES-GCM 落库、日志脱敏。
- 搭建本地零依赖一体化模式（H2 **63** 张表 + 32 站点 / 640 活动合成工作区，27,124 行报表覆盖 1,341 天），
  迁移幂等且不覆盖人工数据；配套 **10 个测试类 / 31 个用例全绿**，
  覆盖图状态流转、护栏越界、检查点重放、控制台鉴权与双人审批。
