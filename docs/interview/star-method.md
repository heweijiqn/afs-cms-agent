# STAR 话术：10 个可以直接背的故事

> 用法：面试官问「介绍一下这个项目」用 S1；问「最难的点」用 S5/S6；问「怎么防止 AI 乱来」用 S2/S3；
> 问「工程化」用 S7/S8。每个故事控制在 **90 秒** 内讲完，不要背成流水账。
>
> 结构：**S**ituation 背景（20s）→ **T**ask 目标（10s）→ **A**ction 我做的（45s，要有取舍）→
> **R**esult 结果（15s，要可核验）。
>
> ⚠️ 下面所有「结果」都限定在可验证范围内（代码、测试、本地合成环境），
> 不要替换成「提升 40%」这类无法自证的商业指标。

---

## S1. 「介绍一下你这个项目」——总述版（必背）

**S｜背景**：广告投放每天要在 Google / Meta / TikTok / Taboola 四个后台之间对数据，运营凭经验砍预算；
就算接了 AI，运营也没法回答「它凭什么建议我砍这个活动」，更不敢让它直接改预算。

**T｜目标**：做一个投放中台，把 AI 建议变成**可验证、可拦截、可追溯**的方案，而不是一个聊天框。

**A｜行动**：我把它拆成三层——
第一层是 CMS 底座（活动/报表/素材/规则/审批，52 个 Controller）；
第二层是编排层，用 LangGraph4j 的编译态 StateGraph 把「规划 ⇄ 取数工具 ⇄ 护栏 ⇄ 反思」串成 8 节点闭环，
支持 STANDARD / DEEP / RULES_ONLY 三种模式；
第三层是治理层，三级安全模式 + Kill Switch + 单次调幅上限 + 日累计变动上限，按台账实时校验。

**R｜结果**：现在整套系统 `java -jar` 一条命令起在 9901，冷启动 8.5 秒，带 32 站点 / 640 活动的合成工作区；
8 个只读工具 + 4 类硬校验让越界建议根本进不了审批队列；10 个测试类 31 个用例全绿。
更有说服力的是运行数据：本地已经真跑了 **78 次优化运行、461 次节点执行、395 次工具调用、127 万 token**，
节点耗时和 token 分布都能在控制台复查。

**收尾金句**：「这个项目我最想讲清楚的一点是——**我不是让 AI 更聪明，我是让 AI 的错误变得可拦截。**」

## S2. 「怎么防止大模型胡说八道？」——护栏节点（最高频追问）

**S｜背景**：模型会给出 `changePercent: 80` 这种明显越界的建议，还会把 `HOLD` 写成负百分比。

**T｜目标**：让「不合规的输出」在系统层面不可能落库，而不是靠提示词祈祷。

**A｜行动**：
1. 先**结构化**：强制模型输出单个 JSON，字段固定（action / changePercent / confidence /
   riskLevel / evidenceRefs / stageDiagnoses / actionItems / experiments / explanation），
   Markdown 围栏自动剥离，解析容错到「找不到 JSON 就退化为文本分析」。
2. 再**硬校验**：guardrail_critic 节点做四类校验——枚举合法、幅度不超上限、符号与动作匹配、
   `HOLD` 必须为 0。
3. 最后**反思回环**：违规不丢弃、不放行，而是把违规原因作为结构化反馈写回 planner，
   让模型带着错误信息重规划一次（`MAX_REVISIONS=1`），仍不合法就落回规则基线。

**R｜结果**：护栏是图里的一个**节点**，不是提示词里的一句话；越界建议不会静默通过，
也不会让整条链路失败，而是走「反馈—修正」这条确定路径。

**可能追问**：「为什么只反思 1 次？」→ 反思次数和延迟/成本强相关；实践中第 2 次修正的边际收益很低，
超过 1 次说明模型能力不够，应该降级到规则而不是继续烧 token。

## S3. 「工具返回的数据太长怎么办？」——上下文预算

**S｜背景**：`dailyReport` 最多返回 40 天 × 7 个字段，外加受众分组和素材分组；
再叠上规则上下文和历史审批，一次请求轻松几万 token。

**T｜目标**：在有限上下文里，保留「决策必需」的信息，砍掉「看起来有用但会挤爆」的信息。

**A｜行动**：
1. **工具结果截断**：单次工具输出上限 6500 字符，超出部分标注「工具输出已截断」，
   让模型知道「后面还有，但我看不到」，而不是以为自己拿到了全部。
2. **历史裁剪**：`historicalRuns` 只取最近 5 次分析与审批意见，不取全量。
3. **节点级 token 记账**：每个节点记录 input/output token 并落库，
   哪一步在烧 token 一眼可见。
4. **日调用预算**：`maxLlmCallsPerDay` 默认 200，超限直接拒绝请求，而不是静默烧钱。

**R｜结果**：一次完整优化运行的 token 消耗可观测、可上限；不会出现「上下文越长、模型越乱」的雪崩。

**可能追问**：「截断会不会丢关键信息？」→ 会。所以顺序是：
先用工具参数收窄范围（只查最近 14 天），再靠截断兜底；截断是保险丝，不是主要手段。

## S4. 「模型挂了你怎么办？」——三级降级链

**S｜背景**：外部 LLM 不可控：限流 429、网关 502、连接重置、Key 过期，甚至返回空消息。

**T｜目标**：模型挂了，产品不能挂。

**A｜行动**：做了一条四段降级链：
1. **瞬态重试**：只有 429 / 502 / 503 / 504 / rate limit / connection reset 才重试 1 次，间隔 600ms；
   SDK 自带重试关掉（`maxRetries(0)`），避免叠加放大。
2. **主备模型切换**：主模型失败自动切 `fallbackChatModel`，两者都失败才抛，异常信息同时带两侧原因。
3. **去工具重试**：如果「带工具调用」失败（有些兼容接口不支持 tools），
   自动去掉工具再调一次，并在结果里标注「已改用无工具模式」。
4. **规则基线**：都失败就走 `rule_baseline` 节点，输出确定性规则建议，并标记来源为 RULES/UNAVAILABLE。

**R｜结果**：前端永远能拿到一个「有来源标注」的结论——
`LANGCHAIN4J_OPENAI_COMPATIBLE` / `RULES` / `UNAVAILABLE` 三态明确，**不会把降级结果伪装成 AI 结论**。

**可能追问**：「降级了用户怎么知道？」→ 返回体带 `source` 和 `note` 字段，UI 上标识「规则基线」，
审批页也能看到。

## S5. 「这个项目最难的技术点？」——把检查点接进 LangGraph4j

**S｜背景**：图执行到一半服务重启，人工审批要能看到「当时停在哪、状态是什么」。

**T｜目标**：把图状态持久化，且要幂等、可追溯、不能拖慢主流程。

**A｜行动**：
1. 实现 LangGraph4j 的 `BaseCheckpointSaver` 接口（list / get / put / release 四个方法）。
2. 建 `agent_checkpoint` 表：`thread_id` 隔离不同 run，`checkpoint_id` 唯一，
   状态整体序列化成 `state_json`。
3. 写入用 H2 的 `MERGE ... KEY(thread_id, checkpoint_id)`，**天然幂等**，
   重放同一节点不会产生重复行。
4. **序列化失败降级**：先尝试 JSON，失败则逐字段 `String.valueOf` 再序列化，
   再失败写 `{}` 并告警——检查点不能成为图执行的单点故障。
5. `threadId = "run-" + runId`，和遥测、审批用同一个 id 串起来，排查时一条链路到底。

**R｜结果**：支持服务重启续跑、支持按 thread 回看节点流转；检查点写入失败不阻断业务。

**可能追问**：「状态大了怎么办？」→ 当前是整图快照，简单但会膨胀；
下一步按节点只存 delta，或加 TTL 清理历史 checkpoint。

## S6. 「怎么做安全兜底？」——四道闸 + 熔断

**S｜背景**：广告预算是不可逆资源，模型一次幻觉可能就是几千块。

**T｜目标**：让「危险的写操作」在四个不同层次上被拦住。

**A｜行动**：
1. **模式闸**：SHADOW 只算不改；COPILOT 要人审批；AUTONOMOUS 才允许自动执行。默认 COPILOT。
2. **Kill Switch**：一键拦截所有写操作（HTTP 423），理由可填，落库留痕。
3. **单次幅度闸**：`maxSingleChangePct` 默认 20，clamp 在 [1,30]，理由是「防止重置广告平台学习期」。
4. **日累计闸**：`dailyBudgetDeltaCap` 默认 500，从 `optimization_ledger` 按
   `action_type='EXECUTE' AND status='COMMITTED'` 聚合**实际已提交变动**，不是按建议算。

再加上**双人审批**：operator 提单、reviewer 审批，`/runs/*/review` 只授给 REVIEWER 角色，
密码强度启动即校验（≥12 字符、≤72 字节、两个账号不能相同）。

**R｜结果**：四道闸是四个独立失败点，任何一道生效都能止损；
而且每一道都有明确的 HTTP 状态码和中文原因，运营看得懂为什么被拒。

**可能追问**：「为什么不直接禁止自动执行？」→ 因为信任要能积累。
SHADOW 跑一段时间、误报率可测之后，才谈得上放权——这是产品节奏问题，不是技术洁癖。

## S7. 「怎么让新人快速跑起来？」——本地零依赖一体化

**S｜背景**：这类项目最常见的死法不是技术难，而是「跑不起来」：
要装 MySQL、配缓存中间件、申请 4 个平台的 API Key、再起一个 Node 服务。

**T｜目标**：`java -jar` 一条命令，5 分钟看到完整界面和数据。

**A｜行动**：
1. **H2 + MySQL 兼容模式**，本地 63 张表，和 MySQL 保持同构。
2. **合成工作区**：两个可重复执行的迁移（`RealisticPlatformDataMigration`、
   `RealisticWorkspaceExpansion`）生成 32 站点 × 20 投放位 = 640 个活动，报表覆盖 1341 个自然日。
3. **迁移幂等且不污染人工数据**：只覆盖种子语料
   （`article_id LIKE 'afs-article-%' AND partner = 'AFS Media'`），
   手工建的活动、规则、凭据一律不改写。
4. **前端产物内嵌 JAR**：部署只有一个文件，不用 Node、不用 Nginx。
5. **启动体验**：端口 9901 监听检测（防重复启动）+ PID 落文件 + 后台 VBS 启动（无黑窗口）。

**R｜结果**：零外部凭据即可演示全流程；迁移可反复重跑，不会越跑数据越多。

**可能追问**：「合成数据会不会让人误判系统能力？」→ 会，所以文档里明确标注「合成工作区」，
只用于验证规模行为与正确性，不作为效果证明。

## S8. 「数据和模型的边界怎么划？」——只读工具 + 不编结论

**S｜背景**：最容易出事的地方不是模型算错，而是**对着空数据编出像模像样的结论**。

**T｜目标**：让「没有数据」时的输出是「没有结论」，而不是「编一个结论」。

**A｜行动**：
1. **工具全只读**：8 个工具没有一个能写库，模型最多只能「建议」。
2. **前置校验**：报表渠道未配置、样本不足、规则缺失时，图直接走 `rule_baseline` 分支，
   并把建议压回 `HOLD`。
3. **规则上限反向注入模型**：`ruleContext` 工具把「预算调整上限、样本阈值、最小花费」直接告诉模型，
   让它知道边界在哪，而不是猜。
4. **情景记忆**：`historicalRuns` 取近 5 次审批意见，避免重复给出**已经被驳回**的建议。

**R｜结果**：模型的所有结论都能追溯到具体工具返回的字段（`evidenceRefs`），
审批页可以直接核对「它引用的那条数据是真的吗」。

**可能追问**：「evidenceRefs 是模型自己写的，怎么保证不编？」→ 目前是弱约束（靠提示词 + 人工复核），
下一步要在代码里做引用校验：evidenceRefs 必须能在工具返回的 JSON 里命中，否则降级为 HOLD。
**这个「下一步」如果被问到，一定要说，它比假装已经解决更加分。**

## S9. 「接口安全怎么做的？」——签名 + 重放防护

**S｜背景**：开放 API 给外部站点调用，需要防篡改、防重放。

**T｜目标**：在沿用存量客户端契约的前提下（它只支持 MD5），把安全做到「够用且可解释」。

**A｜行动**：
1. **签名**：取所有 `HeaderPrefix*` 请求头放 `TreeMap` 排序，拼上 salt 和 body 的 MD5，
   整体再做 MD5 比对。
2. **时间窗**：请求头时间戳与服务端时间差超过 **12 分钟**直接拒。
3. **nonce 一次性**：`ConcurrentHashMap` 记录已用 nonce，保留 13 分钟（窗口 + 1 分钟余量），
   重复即拒——这是防重放的核心。
4. **权限收敛**：`@RootAuth` 注解标记超级管理员接口，普通用户直接 403。

**R｜结果**：篡改 query、篡改 body、重放旧请求三种攻击都被挡住；
代价是 MD5 与内存态 nonce（多实例部署需要换成 Redis）。

**可能追问**：「MD5 不是不安全吗？」→ 是，但它在这里的角色是**签名摘要**不是密码存储，
风险主要在抗碰撞弱。真正的问题是多实例下 nonce 不共享。新接口我会用 HMAC-SHA256 + Redis 存 nonce，
老接口灰度迁移——**这是存量兼容的现实取舍，不吹成最佳实践。**

## S10. 「如果重做一次，你会改什么？」——反思题（一定要准备）

**A｜行动（回答三条，由具体到抽象）**：

1. **检查点改增量**：现在是整图快照，节点一多 `state_json` 会膨胀。
   应该只存 delta + 定期 compaction。
2. **evidenceRefs 做硬校验**：把「引用必须命中工具返回」做成代码约束，
   而不是靠提示词和人工复核。这是从「可信感」到「可验证」的关键一步。
3. **评估集先行**：现在护栏的正确性靠单测和人工看。
   如果重来，我会先攒 50 条「历史真实建议 + 人工判定」做离线评估集，
   每次改提示词或换模型都跑一遍回归——**AI 项目没有评估集，就等于没有单测。**

**收尾**：「这个项目让我最大的认知变化是：AI 应用的工程量不在模型调用，
在**边界的定义**——哪些数据能给、哪些动作不能做、错了怎么退、怎么证明它没乱说。」
