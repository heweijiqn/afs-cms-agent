# 简历怎么写这个项目（3 个版本 + 逐条拆解）

> 配套阅读：`project-map.md`（事实卡，所有数字出处）、`star-method.md`（面试口述版）、`qa-collection.md`（追问应答）。
> 原则：**简历上的每一句，都要能在 `project-map.md` 里找到文件级证据。** 吹出来的数字，面试官追问两层就崩。

---

## 0. 先定「项目叫什么」

简历上不要写内部代号 `afs-cms`（面试官不知道是什么）。给一个可读的名字：

| 版本 | 项目名写法 |
| --- | --- |
| 稳妥 | **海外广告投放管理平台（CMS）与 AI 投放优化中台** |
| 突出 AI | **广告投放 AI Agent 优化平台**（含投放 CMS 后台） |
| 突出业务 | **跨境广告投放与自动化优化系统** |

推荐：`广告投放管理平台与多智能体优化系统` —— 业务在前、AI 在后，面试官第一眼知道做什么，第二眼看到技术含量。

## 1. 版本 A：Java 后端岗（最稳妥，投递面最广）

```
广告投放管理平台与多智能体优化系统 | 后端负责人 | 2025.01 – 2026.11
技术栈：Java 17 / Spring Boot 2.7 / MyBatis / Spring Security / LangChain4j 1.0.1 /
        LangGraph4j 1.5.14 / MySQL / H2 / React 18 + TS + Vite

• 独立完成 CMS 后端 245 个主源码文件、52 个 Controller、42 个 MyBatis Mapper（全注解式、零 XML）的设计与实现，
  覆盖活动管理、渠道报表、内容素材、规则引擎、审批流与开放 API，194 MB 单体 JAR 内嵌前端产物，冷启动 8.5 秒。
• 基于 LangGraph4j 编译态 StateGraph 编排 8 节点优化闭环（上下文摄入 → 策略规划 ⇄ 工具执行 →
  护栏评审 ⇄ 自我反思 → 方案定稿），用条件边实现 STANDARD / DEEP / RULES_ONLY 三模式，
  无模型配置时自动降级为确定性规则，保证功能可用性不依赖外部 LLM。
• 定义 8 个只读 @Tool 数据工具（逐日趋势、国家拆分、创意上下文、规则上限、同业基准、
  历史审批、场景目录、预算试算），把模型约束在「只能用真实数据推理」，越界建议无法进入审批队列。
• 设计四级安全治理：SHADOW/COPILOT/AUTONOMOUS 三级模式 + 全局 Kill Switch +
  单次调幅上限（默认 ±20%）+ 日累计预算变动上限（默认 500），按已提交台账实时校验，防超发。
• 实现 JDBC 检查点（LangGraph4j BaseCheckpointSaver）：agent_checkpoint 表按 threadId 隔离、
  MERGE 保证幂等，支持服务重启续跑与人工审批过程追溯。
• 用 SSE 构建节点级可观测性：agent_execution_trace 落库 + 迟到订阅回放 + 断连自动剔除，
  Token / 耗时 / 工具调用数在控制台实时可见。
• 实现请求签名鉴权（排序取头 + body MD5 + 12 分钟时间窗 + nonce 一次性）与
  operator/reviewer 双人审批（BCrypt、路径级 RBAC、STATELESS），渠道密钥 AES-GCM 落库。
• 闭环已被真跑过：本地工作区累计 78 次优化运行、461 次节点执行、395 次工具调用、127 万 token，
  节点耗时与 token 分布可在控制台复查。
• 搭建本地一体化运行模式（H2 文件库 63 张表 + 32 站点/640 活动合成工作区），
  一条命令启动端口 9901；配套 10 个测试类 / 31 个用例全绿，覆盖图流转、护栏、鉴权与双人审批。
```

**为什么这样写**：每条都是「动作 + 机制 + 可选数字」，没有一条是「使用了 XX 技术」的空话。

## 2. 版本 B：AI 应用 / Agent 工程岗（最吃香，但要扛得住深挖）

```
多智能体广告投放优化平台 | AI 应用工程（后端 + Agent 编排） | 2025.01 – 2026.11
技术栈：LangGraph4j 1.5.14 / LangChain4j 1.0.1 / Java 17 / Spring Boot 2.7 / MySQL / H2

• 设计并实现双图编排：8 节点「投放优化图」（规划 ⇄ 工具 ⇄ 护栏 ⇄ 反思回环）与 2 节点
  「Copilot 多轮图」（agent ⇄ tools，工具轮次上限 6），两图共用 JDBC 检查点与遥测链路。
• 用「护栏即节点」的方式解决 LLM 不可信：guardrail_critic 做枚举/幅度/符号/上限四类硬校验，
  违规触发 self_reflect 把结构化反馈写回 planner 重规划（最多 1 次），把「模型输出」变成
  「可验证的状态机输出」——这是本项目区别于 Demo 的关键设计。
• 工具层 8 个只读 Function Calling 工具，全部参数化、全部返回 JSON、单次输出截断 6500 字符，
  防止长报表挤占上下文；工具异常统一降级为 {"available":false} 而不是抛栈中断图执行。
• 模型网关做工程化兜底：凭据运行时从密钥库热解析（改配置不重启）、瞬态错误（429/5xx/连接重置）
  重试 1 次、主备模型自动切换、全链路 API Key 脱敏，避免密钥进日志与前端。
• 上下文与成本治理：工具结果截断、历史审批只取近 5 次、按节点记录 input/output token，
  日 LLM 调用预算可配（默认 200 次），超限直接拒绝而不是静默烧钱。
• 输出可控：强制单 JSON 结构（action / changePercent / confidence / riskLevel / evidenceRefs /
  stageDiagnoses / actionItems / experiments / explanation），Markdown 围栏自动剥离，
  字段越界由护栏兜底而非提示词硬赌。
• 拒绝对着空数据编结论：报表渠道未配置、样本不足、规则缺失时，图直接走 rule_baseline 分支
  并把建议压回 HOLD，宁可不出结论也不出假结论。
```

**为什么这样写**：AI 岗面试官只关心三件事——**你怎么防幻觉、怎么控成本、怎么让它可运维**，这三条全都答到了。

## 3. 版本 C：全栈岗（前后端都要你的时候）

在版本 A 基础上，把最后一条换成：

```
• 前端 React 18 + TypeScript + Vite 自研控制台：4 组 13 个导航入口、19 个业务模块、
  Ctrl+K 命令面板、签名请求客户端（Web Crypto/JS-MD5）、SSE 流式渲染与失败重连、
  内嵌 JAR 的静态产物打包；本地 H2 模式下免登录密钥即可体验全流程。
```

⚠️ 提醒：全栈版本别写「精通 React」——这个前端是控制台风格（表格/表单/弹窗为主），
被问到 React 并发特性、Suspense、状态管理选型时要能接住，接不住就退回版本 A。

## 5. 技能栏怎么写（别全写「精通」）

```
熟练掌握：Java 17 / Spring Boot / MyBatis / SQL 调优 / RESTful 设计 / 单元与集成测试
熟练使用：LangChain4j / LangGraph4j（StateGraph、条件边、检查点、Human-in-the-Loop）
熟    悉：MySQL 索引与执行计划 / SSE / Spring Security / 请求签名与重放防护
了    解：Redis（缓存三兄弟、`SET NX` 锁的实现与取舍——**项目里刻意没用**，见 Q60）
了    解：React 18 + TypeScript + Vite / H2 兼容模式 / 渠道开放平台 API（Google Ads、Meta、TikTok、Taboola）
```

分级理由：面试官看到「精通 Spring」，就会问 Bean 生命周期 + 循环依赖 + 事务失效三连。
分级不是谦虚，是**控制提问范围**。

## 6. 量化口径表（写之前先对一遍）

| 想写的数字 | 能不能写 | 正确说法 |
| --- | --- | --- |
| **245** 个主源码文件 | ✅ | 可现场数；**别写 257**（257 = 245 主 + 12 测试） |
| 52 个 Controller / **42** 个 Mapper | ✅ | 直接写（42 = dao 32 + publicapi 10） |
| 8 节点 / 8 工具 / 3 模式 | ✅ | 直接写，代码里是常量，接口也返回 |
| **63** 张表 | ✅ | 写「本地 H2 库 63 张表」（36 只是 schema.sql 的 DDL 数） |
| 32 站点 / 640 活动 | ✅ 但要加限定 | 「合成工作区 32 站点 / 640 活动」，不是真实客户 |
| 78 次运行 / 461 节点执行 / 127 万 token | ✅ **强烈建议写** | 唯一的「真跑过」证据，控制台可复查 |
| 31 个用例全绿 / 10 个测试类 | ✅ | 写「10 个测试类 31 个用例全绿」 |
| 194 MB fat jar / 8.5 秒冷启动 | ✅ | 直接写 |
| 286 处映射注解 | ⚠️ 别写 | 含类级注解，容易被追问；写「52 个 Controller」更稳 |
| 358 条提交 | ❌ 绝对别写 | 历史里 300 条是脚本生成的功能点记录 |
| ROAS +40% / CPA −28% | ❌ 别写 | 合成数据的仿真结果，不是真实业务 |
| 「支撑百万级 QPS」 | ❌ 别写 | 没做过压测，一问就穿 |
| 「一次拉 640 个活动」 | ❌ 别写 | 列表接口硬上限 250，640 是库内总量 |

## 7. 反例 → 改写（同一件事，两种写法）

| ❌ 没人信 | ✅ 有人信 |
| --- | --- |
| 使用 LangGraph 实现多智能体系统 | 用 LangGraph4j 编译态图编排 8 节点闭环，条件边实现三模式，无模型时降级规则分支 |
| 实现了安全校验 | 四类硬校验（枚举/幅度/符号/上限）+ 三级安全模式，越界建议触发反思重规划且无法落库 |

| 提升了系统性能 | 工具输出截断 6500 字符、上下文只取近 5 次审批、日 LLM 调用预算 200 次，控住成本与延迟 |

| 系统能跑 | 本地工作区真跑过 78 次运行 / 461 节点 / 127 万 token，遥测页可复查 |
| 测试覆盖率很全 | 10 个测试类 31 个用例全绿，覆盖图流转、护栏越界、检查点重放、双人审批与鉴权 |

## 9. 时间与角色怎么写（避免被问穿）

- **时间**：`2025.01 – 2026.11` 或按你真实投入区间写；如果这是个人项目，就写「个人项目」，
  面试官对个人项目的容错度**高于**包装成公司项目（后者一旦背调就麻烦）。
- **角色**：写「独立开发」比「后端负责人」安全；除非你确实带过人。
- **团队规模**：个人项目不要写「带 3 人团队」。
- **一句话定位**：在项目名后加 `（个人项目，可现场演示）`——这句话能直接把面试官的兴趣拉满，
  因为 90% 的候选人不敢让人现场看代码。
